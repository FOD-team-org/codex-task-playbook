# 검증 지시 (빌드와 다른 새 세션)

```
앱 코드는 수정하지 마라. counterexample-review 스킬로 REQUIREMENTS.md 각 항목의 위반을 찾아라.
DESIGN.md가 있으면 결함마다 설계의 어느 줄(흐름·파일 지도·요구사항 표)과 어긋났는지, 아니면 설계 자체가 틀렸는지 적어라.
요구사항 대조가 끝나면 security-check 스킬로 보안 결함을 따로 찾아라. 변이 검사는 빌드 때 한 결과(DECISIONS.md `## 검증`)를 읽기만 한다.
```

## 제출 전 연습 (검증 세션, 수정이 끝난 뒤)

```
앱 코드는 수정하지 마라. EXPLAIN.md와 DECISIONS.md를 읽고, 설치 때 받은 플레이북 폴더(예: /tmp/playbook)의 docs/WORKFLOW.md `사후 설명 체크`의 유형 1~6으로 질문을 한 번에 하나씩 내라. 실제 파일·함수·수치를 넣고, 질문 하나에는 실제와 다른 전제를 섞되 어느 것인지 말하지 마라. 내가 답하면 맞은 점과 빠지거나 틀린 점을 파일:함수 근거로 두 줄 안에 알려 주고 다음 질문을 내라.
```
