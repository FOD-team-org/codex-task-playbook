# 검증 지시 (빌드와 다른 새 세션)

```
앱 코드는 수정하지 마라. counterexample-review 스킬로 REQUIREMENTS.md 각 항목의 위반을 찾아라.
DESIGN.md가 있으면 결함마다 설계의 어느 줄(흐름·파일 지도·요구사항 표)과 어긋났는지, 아니면 설계 자체가 틀렸는지 적어라.
요구사항 대조가 끝나면 security-check 스킬로 보안 결함을 따로 찾아라. 변이 검사는 빌드 때 한 결과(DECISIONS.md `## 검증`)를 읽기만 한다.
```

## 받은 뒤 할 일

- 결함마다 반례 행을 직접 열어 보고 채택/기각을 정합니다. AI 검증도 사실과 다른 지적을 할 수 있습니다.
- 채택한 것만 BUILD_PROMPT.md의 수정 지시로 넘깁니다.
- 채택/기각과 그 이유를 DECISIONS.md `## 검증`에 V번호로 남깁니다. 기각한 지적은 'AI가 틀렸던 순간'의 재료입니다.
