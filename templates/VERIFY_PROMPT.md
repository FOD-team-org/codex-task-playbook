# 검증 지시 (빌드와 다른 새 세션)

```
app/은 수정하지 마라. REQUIREMENTS.md 각 항목의 위반을 찾아라.
결함마다 그것을 드러내는 최소 입력 행, 기대 결과, 실제 결과를 제시하라.
반례를 대지 못하는 의심은 '근거 약함'으로 따로 분류하라.
서버를 띄워 HTTP로 재현해도 된다. 반례 파일은 app/ 밖에 만들고, 띄운 서버는 종료하라.
요구사항 대조가 끝나면 security-check 스킬로 보안 결함을 따로 찾고, mutation-check 스킬을 app/의 임시 사본에서 돌려 테스트 공백을 보고하라.
브라우저 자동화는 쓰지 마라.
```

## 받은 뒤 할 일

- 결함마다 반례 행을 직접 열어 보고 채택/기각을 정합니다. AI 검증도 사실과 다른 지적을 할 수 있습니다.
- 채택한 것만 BUILD_PROMPT.md의 수정 지시로 넘깁니다.
- 채택/기각과 그 이유를 DECISIONS.md `## 검증`에 V번호로 남깁니다. 기각한 지적은 'AI가 틀렸던 순간'의 재료입니다.
