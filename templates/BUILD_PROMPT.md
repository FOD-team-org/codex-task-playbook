# 빌드 지시 (새 세션)

## 1단계: 설계 (첫 메시지)

```
과제 설명은 README.md, 요구사항은 REQUIREMENTS.md, 자료는 data/에 있다.
코드를 쓰기 전에 design-doc 스킬로 DESIGN.md만 써라. 데이터는 컬럼명과 앞 5줄만 본다.
REQUIREMENTS.md에 없는 보안·결제·운영 판단이 보이면 judgment 스킬로 DECISIONS.md 판단대기에 올려라.
코드는 아직 쓰지 말고, DESIGN.md를 다 쓰면 멈춰라. AGENTS.md 규칙을 따른다.
```

받은 뒤 DESIGN.md를 2~3분 읽습니다. 흐름, 요구사항 표(R이 빠짐없이 있는지), 고장 지도를 봅니다. 이상한 곳이 있으면 아래 2단계 지시의 `바꿀 점`에 적습니다.

## 2단계: 구현 (같은 세션)

```
DESIGN.md대로 구현하라. 바꿀 점: (없으면 "없음")
REQUIREMENTS.md의 항목을 전부 구현하고, 항목마다 node:test로 API 테스트를 하나 이상 만든다(http-roundtrip-test 스킬).
데이터 처리는 data-edge-tests, 고객 데이터를 내보내는 곳은 data-exposure-guard 스킬을 따른다.
결과 파일은 엑셀에서 바로 열리는 UTF-8 BOM CSV로 내려받게 한다.
다 만든 뒤 security-check와 mutation-check 스킬을 한 번씩 돌리고 결과를 DECISIONS.md `## 검증`에 적는다.
끝으로 DESIGN.md를 실제 코드와 대조해 맞춘다.
실행 방법(설치·시작·테스트 명령)을 README.md 맨 아래에 추가한다.
```

## 수정 지시 (같은 빌드 세션)

```
다음 결함만 고쳐라. 다른 부분은 바꾸지 마라.
- (결함 1: 입력 행 / 기대 / 실제)
- (결함 2: …)
결함마다 DESIGN.md 고장 지도에서 원인 위치를 먼저 찾고, 지도에 없던 위치면 그 줄을 더하라.
고친 뒤 전체 테스트를 다시 돌리고, 결함마다 회귀 테스트를 추가하라.
```

## 판단 반영 지시 (같은 빌드 세션)

```
DECISIONS.md 판단기록의 A?~A? 답을 반영하라. 가정과 다른 항목만 고치고 다른 부분은 바꾸지 마라.
항목마다 고친 파일:함수와 추가한 테스트를 그 항목의 `반영:` 줄에 적어라. 답·이유 줄은 고치지 마라.
설계가 바뀌면 DESIGN.md의 해당 줄과 `## 바뀐 점`도 고쳐라.
```
