# 화면 기본기

어떤 디자인 방향이든 화면을 정돈되고 쓰기 쉽게 만드는 기본기다. 색·글꼴·밀도 값은 여기서 정하지 않는다.

## 순서
1. 방향은 design-direction으로 먼저 정한다. 과제나 프로젝트에 디자인 시스템·브랜드가 있으면 그것을 따른다.
2. 기존 화면을 다시 짤 때는 기존 문구·id·입력과 버튼의 동작·API 호출을 유지한다. 구조와 클래스는 바꿔도 된다.
3. 토큰, 공통 클래스, 화면 순서로 만든다.
4. 끝내기 전 점검을 돌린다.

## 토큰과 클래스
- 색·글자 크기·간격·둥글기·그림자·움직임 시간은 토큰 파일 한 곳에 CSS 변수(또는 프로젝트 테마 파일)로 정의하고, 나머지 코드는 변수 이름만 쓴다. 토큰 파일이 없으면 `frontend/src/tokens.css`와 `frontend/src/styles.css` 두 파일로 시작해 진입 파일에서 한 번 불러온다.
- 색 토큰은 역할로 이름 짓는다(바탕, 면, 글자, 보조 글자, 선, 입력 경계, 강조, 강조 위 글자, 링크, 위험). 화면 코드에 색 값 이름(blue-500 등)을 쓰지 않는다.
- 과제·프로젝트가 정한 UI 라이브러리가 있으면 그 테마 기능에 토큰을 넣는다. 정한 것이 없으면 CSS 프레임워크·UI 라이브러리·아이콘 라이브러리를 새로 들이지 않는다.
- 웹폰트는 파일을 프로젝트 안에 두고 시스템 글꼴 폴백을 함께 적는다. 외부 CDN에 기대지 않는다. 숫자 열은 tabular-nums.
- 인라인 style을 쓰지 않는다. 같은 역할에는 같은 클래스를 쓰고, 화면마다 새 모양을 만들지 않는다.
- 아이콘은 기능이 있는 곳(메뉴, 펼침, 상태)에만 둔다. 직접 그리면 인라인 SVG에 currentColor.

## 타입 스케일과 간격
- 글자 크기는 5~7단계만 쓴다(캡션, 보조, 본문, 구역 제목, 페이지 제목, 필요하면 요약 값·큰 제목). 굵기는 2~3개.
- 줄 높이는 본문 1.5 이상, 제목 1.2~1.35. 긴 글 본문 폭은 70ch 안팎에서 끊는다.
- 간격은 4px 배수 단계(4·8·12·16·24·32·48·64)에서만 고른다. 관련 있는 것은 가깝게, 구역 사이는 한 단계 이상 넓게 둔다.

## 앱 구조
design-direction 프리셋의 화면 구성이 내비게이션·목록·상세·주 동작 위치를 먼저 정한다. 이 표는 그 안에서 지킬 규칙이다.

| 영역 | 규칙 |
|---|---|
| 내비게이션 | 화면이 셋 이상이면 사이드바나 상단 바로 고정하고 현재 화면을 표시한다. 좁은 폭에서는 위쪽 가로 바나 메뉴 버튼 |
| 페이지 머리 | 제목은 이 화면의 일이다. 서비스 이름을 되풀이하지 않는다. 주 동작 버튼은 머리 오른쪽 |
| 설명 줄 | 제목 아래 한 문장으로 이 화면에서 무엇을 정하는지 쓴다. 입력 이름을 나열하지 않는다 |
| 도구 줄 | 조건 입력을 한 줄에 둔다. 라벨은 입력 위. 좁으면 줄바꿈 |
| 요약 줄 | 라벨·값 쌍 2~4개를 한 줄에 둔다. 숫자마다 카드를 만들지 않는다. 적용 조건·계산 시각은 아래 캡션 |
| 패널 | 머리 줄(구역 제목, 건수, 보조 동작) 아래 목록이나 표 |

## 목록과 상세
- 사람이 판단하는 묶음(주문·티켓·설비 등)은 목록 행으로 보인다. 행 하나: 상태 표시, ID와 사람이 아는 이름, 핵심 값 2~4개를 고정 폭 열로, 오른쪽 펼침 표시.
- 행을 누르거나 Enter를 누르면 상세가 펼쳐진다(button + aria-expanded + aria-controls, 또는 details/summary). 상세 안의 여러 줄 자료는 표로, 순서가 있는 단계는 단계 목록으로.
- 표: 머리 행은 보조 글자, 행은 아래 선만, hover 면. 숫자 오른쪽, 글자 왼쪽 정렬. 넓으면 표 영역 안에서 가로 스크롤.
- 상태 배지는 점이나 아이콘과 글자로, 버튼처럼 보이지 않게 한다. 주 버튼은 한 화면에 하나, 위험 동작은 위험 색 글자.

## 상태
- 처음 열면 바로 쓸 수 있게 한다. 결과 화면은 기본 조건으로 계산한 결과를, 입력 화면은 다음 행동을 보인다.
- 요청 중: 결과 자리에 글자로 알리고, 제출 버튼은 요청 중에만 끄고 글자를 바꾼다("계산 중…").
- 0건: 이유 한 줄과 다음 행동 버튼. 실패: 이전 결과를 지우고 이유와 다음 행동(다시 시도).
- 제외·경고는 이유별 건수를 보이고 누르면 해당 목록이 펼쳐진다. 처리되지 않은 것을 숨기지 않는다.

## 폼
- 모든 입력에 label을 연결한다. 오류는 필드 옆에 쓰고 aria-describedby와 aria-invalid를 단다. 제출하면 첫 오류로 포커스를 옮긴다.
- 입력에 맞는 type·autocomplete·inputmode를 준다. 붙여넣기를 막지 않는다. 실패해도 입력값을 지우지 않는다.

## 내용과 문구
- 결과를 판단하는 데 필요한 것만 둔다. 라벨은 명사, 버튼은 동사("다시 계산", "저장"). 단위는 열 머리나 값 옆에 한 번.
- 숫자는 Intl.NumberFormat(ko-KR), 날짜·시각은 입력·자료와 같은 형식으로 쓰고 white-space: nowrap.
- 자료와 요구에 없는 조직·사람·장소 이름이나 설명을 지어내지 않는다. 환영·광고 문구를 쓰지 않는다.

## 접근성과 반응형
- 데이터 표는 table·caption·thead·th scope="col". 필터를 바꾸면 "N건 중 M건"을 aria-live="polite"로 알린다.
- 누르는 요소는 button이나 a. :focus-visible에 2px 테두리(바탕 대비 3:1 이상)와 2px 간격. tabindex는 0보다 크게 쓰지 않고, 확대·축소를 막지 않는다.
- 대비: 본문·보조 글자 4.5:1 이상, 큰 글자·입력 경계·아이콘 3:1 이상. 상태는 색과 함께 글자로 구분한다.
- 누름 영역 24×24px 이상, 손가락이 주 입력이면 44×44px 이상.
- color-scheme을 쓰는 모드에 맞춘다. prefers-reduced-motion이면 움직임을 끈다.
- 폭 360px에서 페이지 가로 스크롤 없이 쓴다. 내비게이션은 위쪽 바로, 도구 줄·요약 줄은 줄바꿈, 넓은 표만 자기 영역 안에서 스크롤. 200% 확대에서 글자가 잘리지 않는다.

## 넣지 않는 것
- 흔한 AI 화면 문법: 히어로·환영 문구·소개 문단, 이모지 장식, 반짝이·장식 아이콘·일러스트, 근거 없는 보라·파랑 그라데이션, 반투명 유리 효과, 빛 번짐, 모든 블록에 같은 둥근 카드와 회색 그림자, 카드 안의 카드, 큰 숫자 카드 줄, 제목 위 둥근 사각 아이콘 타일, 색 바탕 위 회색 글자, 한 크기·한 굵기로 위계 없는 글자.
- 요구에 없는 차트·테마 전환·애니메이션·설정 화면.
- design-direction 프리셋이 허용한 효과는 예외로 하고 DESIGN.md에 이유를 쓴다.

## 끝내기 전 점검 (브라우저 없이)
경로는 프로젝트 구조에 맞게 바꾼다. 결과가 0줄이어야 한다.
- 색 값은 토큰 파일에만: `grep -rnE "#[0-9a-fA-F]{3,8}\b|rgba?\(|oklch\(" frontend/src --include=*.css --include=*.tsx | grep -v tokens.css`
- 글자 크기는 변수로만: `grep -nE "font-size:\s*[0-9]" frontend/src/styles.css`
- 인라인 스타일 없음: `grep -rn "style={{" frontend/src`
- 금지 효과: `grep -rnE "gradient|backdrop-filter" frontend/src`. 결과가 있으면 DESIGN.md에 이유가 있어야 한다.
- 의존성(package.json)에 과제·프로젝트가 정하지 않은 화면 라이브러리가 없다.
