# Flutter 테스트 함정

## 언제
- 테스트가 단독으로는 통과하고 묶음으로 돌리면 실패할 때
- 화면 테스트가 기다리지 않고 끝나거나 넘침 오류가 날 때
- 앱과 서버가 같은 이벤트·오류 코드를 쓸 때

## 함정과 대처
| 함정 | 대처 |
|---|---|
| `debugDefaultTargetPlatformOverride` 같은 전역 디버그 값을 바꾸고 안 돌려놓음 | 테스트마다 try/finally로 원래 값으로 돌린다. 다음 테스트가 오염된다 |
| Map·List를 `contains`로 비교 | 구조 비교가 아니다. 내용 비교는 `equals` 매처 |
| 프레임을 예약하지 않는 화면에서 `pumpAndSettle` | 일찍 끝난다. 기다릴 조건(위젯 등장, 횟수)을 명시해 pump한다 |
| 상태 관리 프로바이더 무효화 | 존재 여부(`ref.exists` 등)를 확인한 뒤 invalidate |
| 화면 넘침 오류 | 테스트 화면 크기를 통째로 키우지 않는다. 필요한 범위만 덮어쓴다 |
| 직렬 비동기 큐에서 늦게 끝난 옛 작업 | 세대 토큰을 두고 옛 세대 결과는 버린다 |
| 폴더 쓰기 실패 재현 | 그 경로에 일반 파일을 두어 재현한다 |

## 앱과 서버의 계약
- 이벤트·오류 코드 목록이 앱과 서버에서 정확히 같은지 확인하는 테스트를 둔다.
- 서버 쪽 변경은 추가만 한다. 이미 배포된 옛 앱이 깨지지 않게 한다.

## 실행
- 바꾼 파일의 테스트만 돌린다. 전체 묶음은 사람이 정한 때에만(agent-resource-hygiene).
- 패키지 전역 캐시를 지우지 않는다. 다시 받는 동안 테스트가 대량으로 깨진다.
