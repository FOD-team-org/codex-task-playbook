# 운영 DB 마이그레이션

## 언제
- 컬럼·테이블·인덱스·제약을 바꾸는 마이그레이션이 있는 배포
- "DB는 나중에 하고 코드 먼저", "마이그레이션 먼저 돌려"처럼 순서를 정해야 할 때

## 먼저 볼 것
1. 마이그레이션 파일에서 `DROP`, `TRUNCATE`, `DELETE`, 컬럼 이름·타입 변경, `NOT NULL` 추가를 찾는다. 있으면 따로 보고한다. 지운 데이터는 백업 없이는 되돌릴 수 없다.
2. 배포 파이프라인(빌드 명령, 설치 후 스크립트, 릴리스 훅, 시작 명령)이 마이그레이션을 자동으로 돌리는지 본다. 자동이면 "코드 먼저, DB 나중"이 실제로는 동시에 일어난다. default-stack 구조는 서버가 시작할 때 마이그레이션을 적용하므로, 삭제형 변경은 컬럼을 안 쓰는 코드 배포와 삭제 마이그레이션을 두 번의 배포로 나눈다.
3. 지금 운영 중인 옛 코드와 배치 작업이 바뀌는 컬럼을 쓰는지 grep한다.

## 순서
| 변경 | 순서 | 이유 |
|---|---|---|
| 추가형(새 테이블·컬럼, 기본값 있는 컬럼, 인덱스) | DB 먼저 → 코드 배포 | 새 코드가 없는 컬럼을 읽지 않게 |
| 삭제형(컬럼·테이블 삭제, 이름 변경) | 그 컬럼을 안 쓰는 코드 먼저 배포 → 옛 코드가 다 내려간 뒤 DB | 옛 코드가 지워진 컬럼을 읽지 않게 |
| 바꾸기(타입 변경, 이름 변경) | 새 것 추가 → 양쪽에 쓰기 → 읽기 전환 → 옛 것 삭제로 나눈다 | 한 번에 바꾸면 어느 순서든 깨진다 |
- 삭제 전에 지울 데이터의 백업(덤프나 스냅샷)을 만들고 복구 방법을 적는다.
- 각 단계 전후로 마이그레이션 기록 테이블의 행 수(적용된 개수)를 적는다.

## 승인
- 운영 DB 적용과 운영 배포는 단계마다 사람 승인을 받는다.
- 삭제형 단계는 백업 위치와 함께 따로 승인을 받는다.

## 접속 문자열
- 운영 DB 접속 문자열을 셸 환경 변수로 내보내 두지 않는다(`export` 금지). 다음 명령(마이그레이션, 시드, 테스트)이 실수로 운영을 건드린다. 필요한 명령 한 번에만 넣고, 값은 사람이 넣는다.
- 서버리스 DB는 커넥션 풀링 주소와 직접 주소를 구분해 쓰고(마이그레이션은 보통 직접 주소), 앱 서버와 같은 지역인지 본다. 무료 등급의 한도(저장량, 연결 수, 정지 정책)를 운영 문서에 적는다.

## 하지 않는 것
- 승인 없는 운영 DB 적용, 파괴적 구문을 보고 없이 적용
- 삭제형 변경을 DB부터 적용
- 운영 접속 문자열을 셸에 남기기, 출력하기
