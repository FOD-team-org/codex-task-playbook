# 배포 준비 확인

내 작업 폴더에서 도는 것과 남의 서버에서 도는 것은 다르다. 남아 있는 빌드 결과, 전역 도구, 내 환경 변수 없이도 도는지 확인한다.

## 확인
| 항목 | 방법 | 통과 기준 |
|---|---|---|
| 깨끗한 복사본 | node_modules·dist·.env·로그를 뺀 작업 폴더를 작업 폴더 밖 임시 폴더(os.tmpdir)에 복사한다. 작업 폴더 안에 만들면 지우지 못할 때 산출물에 섞인다. 거기서 lock 파일대로 설치(`npm ci`)하고, README의 시작 명령으로 띄워 요청 1회를 보낸 뒤 끈다 | README 명령만으로 켜지고 응답이 온다. 설치가 네트워크로 막히면 `미확인` |
| 환경 변수 | 코드가 읽는 변수 이름(`process.env.` 등)을 검색해 `.env.example`·README와 대조한다 | 빠진 이름 0. 필수·선택과 기본값이 README에 있다 |
| 비밀값 | 키·비밀번호·토큰으로 보이는 문자열과 `.env`가 커밋될 파일에 없는지 검색한다 | 0건 |
| 바인딩·포트 | 0.0.0.0 바인딩과 PORT 환경 변수 | localhost 바인딩·고정 포트 없음 |
| 데이터 준비 | 빈 DB에서 시작해 마이그레이션·적재가 끝나는지, 두 번째 시작에도 오류가 없는지 | 두 번 다 성공 |
| 배포 파일 | 프로젝트에 있는 Dockerfile·compose 등. docker가 있으면 한 번 띄워 요청 1회 | 뜨고 응답한다. docker가 없으면 `이미지 빌드 미확인` |
| 정리 | 띄운 서버와 임시 폴더를 정리한다 | 남은 프로세스 0 |

## 운영 메모
README 실행 방법 아래에 `상황 | 할 일` 표 하나만 더한다.
- 담을 상황: 다시 시작, 로그 위치, 자료 다시 넣기, 이전 버전으로 되돌리기.
- 배포 방식이 정해져 있으면 그 방식으로 쓴다. 정하지 않은 운영 방식은 지어 내지 않고 `정해지지 않음`으로 둔다.

## 보고
- 마지막 보고에 `항목 | 결과(통과·실패·미확인) | 실행한 명령` 표로 위 점검표의 줄마다 적는다.
- 확인 중에 찾아 고친 결함은 작업 지침의 문제 기록 형식으로 남긴다.

## 하지 않는 것
- 실제 서버로 배포·업로드·이미지 push를 하지 않는다. 사람이 한다.
- 확인하려고 전역 도구나 docker를 설치하지 않는다.
- 상태 확인 주소, 모니터링, 로그 수집 같은 운영 기능을 요구 없이 더하지 않는다.
