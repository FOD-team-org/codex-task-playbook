# 판단대기

## 무엇을 올리나
REQUIREMENTS.md(PRD)에 없는 로직 중, 틀리면 서비스에 문제가 생기는 것만 판단대기에 올린다.
- 보안: 인증·권한, 개인정보 노출·마스킹, 비밀값, 외부 입력 검증
- 결제·금액: 돈·수량·요금 계산, 반올림, 환불·취소
- 운영: 데이터 삭제·덮어쓰기, 외부 발송, 장애·성능·복구에 영향을 주는 동작

자주 나오는 예: 마스킹 형식이 없음, CSV 수식 문자 처리(data-exposure-guard), 관리자 경로 보호 방식, 호출 한도·차단 길이처럼 숫자가 없는 보안 기준값.

REQUIREMENTS.md에 답이 있으면 그대로 따르고 올리지 않는다. 그 밖의 판단(문구, 정렬, 화면 배치, 내부 구조, 일반 경계값)은 직접 정하고 ASSUMPTIONS.md에 `- 무엇 — 정한 내용 / 이유 / 파일:함수` 한 줄로 적는다.

## 올리는 법
멈추지 않는다. 추천안을 가장 작은 구현으로 넣고 계속 진행한 뒤, 마지막 보고에 올린 번호를 적는다. DECISIONS.md의 `## 판단대기` 절에 아래 틀로 등록한다(절이 없으면 만든다).

```
### A<번호> <제목>
- 배경: <두 문장 안>
- 선택지: ① 선택1 ② 선택2
- 추천: <추천과 이유>
- 추천대로 두면: <담당자가 화면·파일에서 보게 될 결과 한 문장>
- 영향: <파일:함수>
- 답:
- 이유(내 말로):
```

`추천대로 두면`은 코드 용어 없이 쓴다. 예: "할인 금액은 원 단위에서 반올림되어, 보고서 합계가 건별 합과 몇 원 다를 수 있다."

## 답을 받은 뒤
- `답:`과 `이유(내 말로):`는 사람이 쓴다. 비어 있으면 채우지 않는다. 채팅으로 받은 답은 원문 그대로 옮긴다.
- 답이 모호하면 임의로 정하지 않고 마지막 보고에서 다시 묻는다.
- 답이 적힌 항목은 질문·답 원문과 함께 `## 판단기록`으로 옮긴다. 판단대기에는 열린 항목만 남긴다.
- 세션을 시작하거나 수정 지시를 받으면 `## 판단기록`을 먼저 읽는다. 답이 추천과 다르면 답대로 고치고, 고친 파일:함수와 테스트를 그 항목의 `반영:` 줄에 적고 `추천과 달랐나: 예`로 표시한다.
