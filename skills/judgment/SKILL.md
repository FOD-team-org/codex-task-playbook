# 판단대기
사람이 인터뷰를 요청한 경우에만 채팅으로 묻고 `대기: 사용자`로 멈춘다. 구현·검증 중에는 멈추지 않고, 등록한 항목의 추천안을 가정으로 삼아 진행한 뒤 마지막 보고에 적는다. 유한 선택지·승인·미결 사항은 DECISIONS.md의 `## 판단대기` 절에 등록한다(절이 없으면 만든다).
미룬 인터뷰 문항은 REQUIREMENTS.md의 `미확인 / 가정`에 문항 ID와 함께 적는다.
그 외는 항목마다 다음 필드를 적는다.

```
### A<번호> <제목>
- 배경:
- 선택지: ① 선택1 ② 선택2
- 추천: <추천과 이유>
- 임시 진행: <추천안을 가정으로 진행함 / 멈춤>
- 영향: <파일:함수>
- 막는 작업: <T>
- 상세: <문서 경로, 없으면 생략>
- 답:
- 이유(내 말로):
```

작업이 없는 프로젝트 단계는 `막는 작업: -`로 등록하고 답을 기다린다.
답은 번호 하나 또는 자유 서술. 승인 동작은 번호나 승인/진행 토큰이 있어야 한다. 조건부 답은 조건을 함께 보존한다.
모호한 답이나 질문 개정과 맞지 않는 답은 재질문하며 임의 승인하지 않는다. 답을 받으면 `답:`에 원문을 적은 뒤 그대로 적용한다.
답 없이 항목을 완료 처리하지 않는다. `답:`과 `이유(내 말로):`는 사람이 쓴다. 채팅으로 받은 답이면 원문을 그대로 옮기고, 비어 있으면 채우지 않는다.
세션을 시작하거나 수정 지시를 받으면 `## 판단기록`을 먼저 읽는다. 답이 가정과 다르면 답대로 고치고, 고친 파일:함수와 테스트를 그 항목의 `반영:` 줄에 적는다. 추천과 다른 답이면 `추천과 달랐나: 예`로 표시한다.

제목 60자·배경 400자·선택지 하나 160자·추천 200자 안으로 짧게 쓴다. 배경은 두 문장 안으로 쓴다. 긴 근거는 프로젝트 문서에 쓰고 `상세:`에 경로로 연결한다(존재하는 파일, DECISIONS.md 자신 제외).
결정된 항목은 DECISIONS.md의 `## 판단기록` 절로 옮기며 질문·답 원문을 함께 보존한다. 판단대기에는 열린 판단만 남긴다.
