# 디자인 방향 정하기

화면의 색·글꼴·밀도·화면 구성을 상황에 맞는 프리셋 하나로 정하고 기록한다. 화면을 짓는 기본기는 ui-baseline이 맡는다.

## 언제
- 새 서비스나 새 화면의 첫 화면을 만들 때.
- 색·글꼴·밀도가 요구사항·DESIGN.md·기존 코드 어디에도 없을 때.
- 사람이 "이런 느낌 말고", "너무 딱딱하다"처럼 방향 자체를 바꾸라고 할 때. 이때는 상황 읽기 표를 다시 채우고 다른 프리셋을 고른다.

## 순서
1. 이미 정해진 것을 찾는다: 과제 파일, REQUIREMENTS.md, DESIGN.md, 기존 토큰·테마 파일, 브랜드 가이드, 사람의 지정. 있으면 그대로 쓰고 2~3을 건너뛴다. 빠진 칸(예: 어두운 모드)만 고른 프리셋 값으로 채운다.
2. 아래 상황 읽기 표를 요구사항·자료에서 채운다. 근거가 없는 칸은 "근거 없음"으로 두고 추측으로 채우지 않는다.
3. 판단표에서 프리셋 1~2개를 고른다. 칸끼리 다른 프리셋을 가리키면 신뢰 칸, 주 사용자 칸, 제품 종류 칸 순서로 따른다. 값은 `references/styles.md`에 있다.
4. 선택을 한 줄로 기록한다. DESIGN.md가 있으면 그 안에, 없으면 결정 기록(DECISIONS.md·ASSUMPTIONS.md 등)에 `디자인 방향: <id> / 이유: <상황 칸 두 개> / 버린 후보: <id>` 꼴로 쓴다.
5. 고른 프리셋의 토큰을 코드 한 곳(CSS 변수 파일이나 프로젝트 테마 파일)에 옮긴다. 화면 코드는 변수 이름만 쓴다. 모드는 요구에 있는 것만 만든다.
6. 프리셋의 화면 구성 칸대로 내비게이션, 목록 표현, 상세 여는 방식, 주 동작 위치를 정한다. 다른 구성이 필요하면 이유를 4번 기록에 덧붙인다.
7. 사람이 시안 비교를 원하면 프리셋 2~3개로 같은 화면 한 장을 만들어 나란히 보인다. 토큰 파일만 바꿔 끼우게 만들고, 사람이 고르면 나머지 토큰 파일은 지운다.
8. 네트워크를 쓸 수 있으면 `references/reference-study.md` 절차로 같은 분야 화면 3~5개에서 원리를 뽑아 바꿀 칸만 바꾼다. 네트워크가 없으면 프리셋 값만으로 진행한다.

## 묻지 않고 진행하는 환경
무인 실행이나 시험처럼 사람에게 물을 수 없거나 묻지 말라는 환경이면 판단표에서 하나를 골라 4번대로 기록하고 진행한다. 7번 시안 비교와 8번 레퍼런스 조사는 하지 않는다. 글꼴 파일이 프로젝트에 없으면 내려받지 않고 프리셋 글꼴 칸의 시스템 글꼴 폴백만 쓴다.

## 상황 읽기 표
| 칸 | 채울 내용 | 근거 찾을 곳 |
|---|---|---|
| 제품 종류 | 업무 도구, 대시보드, 소비자 앱, 커머스, 콘텐츠, 공공·금융, 교육, 엔터 | 과제 문장, 기능 목록 |
| 주 사용자·나이 | 직무, 나이대, 디지털 익숙함 | 요구사항의 사용자 설명 |
| 사용 빈도·정보 밀도 | 매일 오래 쓰는가 / 한 화면에 보일 항목 수 | 화면 목록, 자료 건수 |
| 신뢰 | 돈·개인정보·행정 처리가 있는가 | 기능 목록, 자료 항목 |
| 감성 톤 | 차분, 친근, 활기, 개성 | 브랜드·사람 지정 |

## 판단표
| 상황 | 1순위 | 2순위 |
|---|---|---|
| 직원·개발자가 매일 쓰는 업무 도구 | saas | dense |
| 표·차트가 화면 대부분인 모니터링·분석 | dense | saas |
| 일반 소비자가 폰으로 가끔 쓰는 생활 앱 | friendly | commerce |
| 상품을 고르고 사는 화면 | commerce | friendly |
| 긴 글·기사·문서를 읽는 화면 | editorial | trust |
| 돈·행정·개인정보를 다루는 신청·조회 | trust | senior |
| 60대 이상이 주 사용자, 접근성 요구 명시 | senior | trust |
| 브랜드 소개·캠페인·포트폴리오 | expressive | editorial |
| 강의·문제 풀이·진도 | education | friendly |
| 영상·음악·게임 탐색 | media | expressive |

- 고령층이 주 사용자이거나 접근성 요구가 있으면 다른 프리셋을 골라도 senior의 글자 크기·대비·누름 영역 하한을 함께 적용한다.
- 상황 칸 대부분이 근거 없음이면 saas 어두운 모드로 시작하고 기록의 이유 칸에 "근거 없음, 기본값"이라고 쓴다.
- 브랜드 색이 정해져 있거나 감성 톤·업종이 프리셋 강조색과 맞지 않으면 강조색만 `references/color-combinations.md` 절차로 바꾸고 대비를 다시 계산한다.

## 확인
- 4번 기록 한 줄이 DESIGN.md나 결정 기록에 있다.
- 색 값이 토큰 파일 한 곳에만 있다(ui-baseline 끝내기 전 점검).
- 프리셋 색을 하나라도 바꿨으면 대비를 다시 계산해 기록했다. 글자 4.5:1(senior 7:1), 입력 경계 3:1 이상.
- 한 화면에 두 프리셋의 값이 섞이지 않았다.
- 프리셋을 바꿨으면 색만이 아니라 화면 구성도 그 프리셋대로 바뀌었다.

## 하지 않는 것
- 기존 디자인 시스템·브랜드가 있는데 프리셋으로 덮어쓰지 않는다.
- 프리셋 여러 개를 섞어 즉석 조합을 만들지 않는다. 바꿀 때는 칸 단위로 바꾸고 기록한다.
- "요즘 유행"을 이유로 방향을 고르지 않는다. 이유는 상황 칸으로 쓴다.
- 레퍼런스 화면의 로고·사진·문구·고유 색 조합을 가져오지 않는다.
- 프리셋을 고르고 화면 구성은 기본 사이드바·표 그대로 두지 않는다.
