# 여러 저장소 작업 공간

## 언제
- 한 기능이 정본(스키마·규정 문구·공용 데이터) 저장소와 그것을 쓰는 저장소에 걸칠 때
- 다른 저장소의 데이터를 사본으로 들고 있는 저장소를 갱신할 때
- 여러 저장소가 같은 DB를 쓰는데 스키마를 바꿀 때

## 작업 단위
- 작업 하나는 저장소 하나에서 한다. 여러 저장소에 걸치면 저장소별 작업으로 나눈다.
- 시작 전에 지금 폴더와 브랜치를 확인한다.
- 정본 저장소를 먼저 병합하고, 소비 저장소는 그 뒤에 올린다.
- 남의 담당 저장소의 main은 읽기만 한다.
- 워크트리에서 패키지 설치를 새로 하지 않는다. 의존성은 원래 체크아웃에서 관리한다.

## 정본 스냅샷 동기화
- 소비 저장소는 정본의 사본(스냅샷)과 함께 출처 정보 파일(정본 저장소, 커밋 SHA, 가져온 시각)을 둔다.
- 사본과 정본이 어긋나면 실패하는 드리프트 테스트를 둔다.
- 갱신은 정본을 먼저 바꾸고, 소비 저장소는 사본·출처 정보·영향받는 코드를 PR 하나에 묶는다.
- 규정·법률·의료 같은 규제 문구는 사본을 옮길 때 바꿔 쓰지 않는다. 글자 그대로 옮긴다.

## 스키마가 바뀌는 배포
- 정본 저장소에 스키마가 있고 여러 소비 저장소가 같은 DB를 쓰면, 모든 소비 저장소의 옛 코드가 바뀌는 컬럼을 쓰는지 먼저 grep한다.
- DB와 코드의 순서, 파괴적 구문 점검, 접속 문자열 취급은 prod-db-migration을 따른다.

## 하지 않는 것
- 소비 저장소를 먼저 병합하기, 사본만 고치고 정본은 두기
