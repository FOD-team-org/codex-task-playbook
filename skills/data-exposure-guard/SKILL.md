# 데이터 노출 방지

1. 응답은 내보낼 필드만 골라 새 객체로 만든다. 원본 행이나 객체를 res.json에 그대로 넣지 않는다. 화면에서만 가리면 가린 것이 아니다. API 응답에서부터 가린다.
2. 가리는 형식이 REQUIREMENTS.md에 있으면 그대로 따른다. 없으면 judgment 스킬로 판단대기에 올리고 추천안으로 진행한다. 추천안은 전화번호 010-****-5678, 이름 홍*동, 이메일 앞 두 글자+***@도메인, 주소 시·구까지다.
3. 가리기 전에 형식을 정규화한다(숫자만 남기고 자릿수 확인). 형식이 이상한 값은 전부 가린다.
4. 원문이 꼭 필요한 화면(관리자 등)은 별도 경로에서만 내보낸다. 그 경로는 security-check의 인증 항목을 따른다.
5. 로그와 오류 메시지에는 개인정보와 비밀값을 쓰지 않는다. 행을 가리킬 때는 ID만 쓴다.
6. 조회가 실패하면 이유를 구분하지 않는다. "없는 주문"과 "연락처가 틀림"에 같은 상태 코드와 같은 문구를 준다.
7. CSV 내보내기
   - 맨 앞에 UTF-8 BOM(﻿)을 붙인다. 없으면 엑셀에서 한글이 깨진다.
   - 쉼표, 큰따옴표, 줄바꿈이 든 셀은 큰따옴표로 감싸고, 안의 큰따옴표는 두 번 쓴다.
   - 데이터에서 온 텍스트 셀이 = + - @ 탭 CR LF(전각 ＝＋－＠ 포함)로 시작하면 앞에 작은따옴표(')를 붙인다. 숫자 값(서버 계산값, 숫자 열)은 그대로 둔다. 이 처리는 화면에 보이는 값을 바꾸므로 판단대기에 올려 사람이 확인하게 한다.
   - 가리기 규칙은 내보내기에도 똑같이 적용한다.
   - Content-Type은 `text/csv; charset=utf-8`, 파일 이름은 Content-Disposition의 `filename*=UTF-8''`로 준다.
8. 항목마다 테스트를 하나씩 둔다. 응답 본문에 원문 전화번호가 없다. CSV 처음 3바이트가 EF BB BF다. `=1+1` 셀이 `'=1+1`로 나온다. 쉼표가 든 셀이 감싸져 있다. 두 종류의 조회 실패 응답이 같다.
