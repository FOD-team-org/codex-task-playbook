# 외부 시스템 연동

우리가 고칠 수 없는 상대와 붙는 일이다. 상대의 실제 모양을 먼저 확인하고, 상대가 바뀌거나 멈춰도 고칠 곳이 한 군데가 되게 만든다.

## 순서
1. 계약을 모은다: API 문서, 예시 요청·응답, DB 스키마, 파일 형식, 인증 방식, 호출 한도. 문서와 예시 응답이 다르면 예시를 따르고, 다른 점을 결정 기록에 적는다.
2. 필드 대응표를 DESIGN.md 데이터 항목에 적는다: `상대 필드 | 우리 필드 | 변환 | 빈값·이상값 처리`.
3. 연동 코드는 시스템마다 파일 하나(예: `backend/src/<시스템>/<시스템>.client.ts`)에만 둔다.
   - 주소·계정·키는 환경 변수로 받고, `.env.example`에는 이름만 적는다.
   - 다른 코드는 이 파일의 함수만 부르고, 상대의 응답 모양을 직접 다루지 않는다.
4. 호출마다 시간 상한을 둔다. 문서에 값이 있으면 그 값을 쓴다. 없으면 화면 요청 안에서 부르는 호출은 화면 응답 기준보다 짧게(2초 기준이면 1.5초), 화면과 떨어진 일괄 작업은 5초로 하고 ASSUMPTIONS.md에 적는다. 여러 건을 부르면 동시에 보내 전체 시간이 상한 하나 안에 들게 한다.
   - 시간 초과, 4xx, 5xx, 모양이 다른 응답을 서로 다른 오류로 바꾼다.
   - 화면과 로그에서 무엇이 실패했는지 보이게 한다.
   - 재시도·대기열·회로 차단은 요구에 있을 때만 넣는다.
5. 상대에 쓰는 호출(생성·수정·삭제·발송)은 개발과 테스트 중에 실제 상대로 보내지 않는다.
   - 시험용 주소나 가짜 상대를 쓴다. 실제로 보낼지는 사람이 정한다.
   - 상대가 멱등 키 같은 수단을 주면 써서, 같은 요청이 두 번 가도 한 번만 반영되게 한다.
6. 기존 DB에는 읽기로만 붙는다. 테이블 만들기·고치기·마이그레이션은 우리 DB에만 한다. 상대 DB를 바꿔야 하면 SQL 파일을 만들어 사람에게 넘긴다.
7. 테스트는 예시 응답으로 만든 가짜 상대로 돌린다(테스트 안에서 띄우는 작은 HTTP 서버나 고정 응답 함수).
   - 정상 응답 1개와, 실패 종류(시간 초과, 오류 코드, 모양 다름)마다 1개씩 둔다.
   - 실제 상대 없이 통과해야 한다.
8. 실제 상대에 붙을 수 있으면 읽기 호출 한 번으로 연결과 응답 모양을 확인하고, 상태 코드와 건수를 기록한다. 붙지 못했으면 마지막 보고 미완에 `<시스템> 실연결 미확인`으로 적는다.

## 하지 않는 것
- 키·토큰을 코드, 테스트, 로그, 문서에 넣지 않는다. 오류 메시지에 요청 헤더나 응답 본문 전체를 싣지 않는다.
- 상대의 응답을 그대로 화면에 넘기지 않는다. 대응표에 있는 필드만 옮긴다(data-exposure-guard).
- 문서에 없는 엔드포인트를 찾아 부르거나 화면 긁기로 대신하지 않는다. 계약이 모자라면 판단대기로 올린다(judgment).
- 기능 하나 때문에 상대 SDK 같은 큰 의존성을 들이지 않는다. 표준 fetch로 되면 fetch를 쓴다.
