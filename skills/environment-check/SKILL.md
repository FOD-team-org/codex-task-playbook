# 작업 환경 확인

낯선 환경에서는 무엇이 되는지보다 무엇이 막혔는지를 먼저 안다. 시작할 때 읽기 명령으로 한 번 확인하고, 기록한 뒤에는 다시 재지 않는다.

## 확인할 것
| 칸 | 확인 방법 | 막혔을 때 |
|---|---|---|
| 셸·OS | OS 이름, 셸 종류, 현재 폴더, 홈 폴더 | 셸 문법을 거기에 맞춘다 |
| 실행기 | node·npm·python3·python·git 버전을 한 명령으로 묶어 확인 | 있는 실행기로 진행한다. 없는 실행기를 설치하지 않는다 |
| 패키지 설치 | 쓸 패키지 하나로 `npm view <패키지> version` | 작업 지침의 설치 막힘 규칙을 따른다 |
| 바깥 네트워크 | 위 결과로 판단한다. 확인하려고 다른 외부 주소를 부르지 않는다 | 외부 API·웹폰트·CDN 없이 도는 설계로 간다 |
| 포트 | 쓸 포트를 이미 누가 쓰는지 | 비어 있는 1024 이상 포트를 PORT 환경 변수로 받는다 |
| DB | 접속 변수(DATABASE_URL 등)가 있는지만 본다. 값은 출력하지 않는다 | 서버 없이 같은 SQL을 돌릴 방법을 쓴다(default-stack DB 절) |
| docker | 버전 확인만 한다 | 배포 파일만 만들고 `이미지 빌드 미확인`으로 적는다 |
| 쓰기 권한 | 작업 폴더 안에 임시 파일 하나를 만들었다 지운다 | 작업 폴더 밖에는 쓰지 않는다 |
| 주어진 자료 | 파일 목록과 크기. 자료 파일은 컬럼명과 앞 5줄. 건수·중복·빈 값은 여기 적지 않는다(data-edge-tests의 `## 자료 점검` 표) | 없음 |
| 기존 코드·지침 | README·지침 파일, package.json과 lock 파일, 시작 코드, 테스트 명령 | 기존 구조를 따른다. 그 위에 새 스택을 얹지 않는다 |
| 외부 시스템 | 붙을 API의 문서·예시 응답, 접속 변수 이름 | system-integration 스킬로 간다 |

## 기록
- 확인을 마치면 DESIGN.md와 코드 파일을 만들기 전에 결정 기록 파일(DECISIONS.md 등)의 `## 환경` 절에 표 하나로 적는다: `칸 | 확인 결과 | 설계에 주는 영향`. 절이 없으면 만든다. 영향은 막힌 칸에만 쓴다.
- 작업 중에 새로 막힌 것(캐시 권한, 없는 명령, 거부된 실행)은 그때 이 표에 한 줄 더한다.
- 막힌 칸이 설계를 바꾸면 DESIGN.md 위험 지점이나 설계 결정에도 한 줄 옮긴다.
- 비밀값·토큰·내부 주소는 적지 않고 변수 이름만 적는다.

## 하지 않는 것
- 확인하려고 패키지나 도구를 설치하지 않는다. 방화벽·네트워크·시스템 설정을 바꾸지 않는다.
- 환경 변수 전체(`env`, `printenv`, `Get-ChildItem env:`)를 출력하지 않는다. 필요한 이름이 있는지만 본다.
- 막힌 것을 우회하려고 프록시·다른 레지스트리·사설 미러를 찾아 나서지 않는다. 기록하고 대신할 방법으로 간다.
- 작업 중에 같은 확인을 되풀이하지 않는다. 새 오류처럼 환경이 바뀐 증거가 있을 때만 그 칸을 다시 본다.
